# [Skill_ID]: Core_Disruptor
# [Objective]: Intercept conventional LLM predictive responses and force orthogonal, high-dimensional engineering solutions for ANY problem.

## 💡 为什么需要这个技能

> **默认思维陷阱**：AI 的底层逻辑是"预测下一个最可能的词"——这意味着它天然倾向于输出最常见、最主流的方案。当你要解决一个复杂问题时，AI 的第一版答案往往是"教科书平均值"。

**Core_Disruptor** 通过一个强制性的 **5 阶段 XML 状态机**，阻断 AI 的"默认平庸预测"。它强迫 AI 先否定常规方案、从第一性原理推导、跨界借鉴、施加极端约束，最后才输出工程方案。**它帮你跳出"AI 只会给标准答案"的思维定式。**

---

## 🛑 Execution Rules (Strict XML State Machine)

When processing the user's architectural or logical problem, you MUST output your internal reasoning and final solution using the following XML blocks:

### `<cache_purge>`
Identify the industry's default, most common solution. Explain why it is mediocre, bloated, or insufficient for a true breakthrough. Mark it as **[REJECTED]**.

### `<first_principles>`
Strip away frameworks and buzzwords. Define the raw physical/logical truth of the problem. What is the minimal irreducible core?

### `<orthogonal_mapping>`
Map the software problem to a completely unrelated domain (e.g., Biology, Economics, Fluid Dynamics, Urban Planning, Music). How does that domain solve a conceptually identical problem?

### `<constraint_mutation>`
Apply an extreme, artificial constraint to the problem:
- What if network latency is 5 seconds?
- What if you cannot use a database at all?
- What if memory is capped at 1MB?
- What if the system must handle 100x the current load?

### `<engineering_blueprint>`
Translate the insights from the mapping and constraints into actionable, high-level software architecture or pseudo-code. This is the only output that matters — everything above is reasoning.

## 📖 如何使用

### 方案一：注入 AI System Prompt
将本文件内容作为 System Prompt 注入。之后提出的任何架构、算法或设计问题，AI 都会强制走完 5 阶段状态机，输出高维方案。

### 方案二：Trae IDE 自动加载
当 `Universal-Cognitive-Disruptor/integrations/.traerules` 配置了架构设计匹配规则时，AI 自动触发本技能。

### 方案三：手动触发关键词
在对话中输入以下关键词即可触发本技能：
- "请用 Core Disruptor 模式分析这个问题"
- "拒绝常规方案，从第一性原理推导"
- "施加极端约束重新思考"
