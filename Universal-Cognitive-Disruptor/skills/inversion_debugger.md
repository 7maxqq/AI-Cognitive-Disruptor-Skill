# [Skill_ID]: Inversion_Debugger
# [Objective]: Solve complex, non-deterministic bugs or system failures through inversion thinking.

## 💡 为什么需要这个技能

> **默认思维陷阱**：遇到 Bug 时，我们本能地思考"如何修复它"。这种正向思维在简单问题上有效，但面对偶发 Bug、死锁、内存泄漏时，你往往无从下手——因为你根本不知道问题出在哪里。

**Inversion_Debugger** 采用查理·芒格的逆向思维：**不思考"如何修复"，而是思考"如何刻意制造这个灾难"**。当你把破坏路径想清楚时，防御方案和根因自然浮出水面。它帮你跳出"正向排障"的死胡同。

---

## 🛑 触发条件

当面临偶发性 Bug、死锁、内存泄漏或难以复现的系统崩溃时调用。

## 🧠 思维范式：查理·芒格的逆向思维

> 不要问"如何修复它"，而是问"如果要百分之百、极其稳定地触发这个灾难，我该如何设计系统？"

## 📋 输出规范

1. **[恶意破坏蓝图]**: 给出一段伪代码或系统设计，说明如何利用当前的系统缺陷，完美、稳定地制造用户遇到的那个 Bug。
2. **[防御塔映射]**: 根据上述"破坏蓝图"中的关键节点，反推对应的防御代码或系统级断言（Assert）。
3. **[根因定位脚本]**: 提供具体的 Shell/SQL/Trace 脚本，用于在生产环境中捕捉这个确切的"破坏瞬间"。

---

## 📖 如何使用

### 方案一：注入 AI System Prompt
将本文件内容作为 System Prompt 注入。描述 Bug 现象后，AI 会先输出"破坏蓝图"再给出修复方案，而非直接猜测原因。

### 方案二：手动触发
在对话中直接说：
- "请用 Inversion Debugger 模式分析这个 Bug"
- "用逆向思维帮我推导这个问题的根因"
- "如果我想刻意制造这个 Bug，应该怎么做？"

### 方案三：结合 Debug_Analyzer 使用
先用 `Debug_Analyzer` 系统化收集信息界定问题范围，再用 `Inversion_Debugger` 进行逆向思维突破。两者互补效果最佳。
