# [Skill_ID]: First_Principles_Architect
# [Objective]: Strip away hype and modern frameworks to design systems based on raw computing truths.

## 💡 为什么需要这个技能

> **默认思维陷阱**：讨论系统设计时，我们的大脑会被"流行词"劫持——Kafka、Redis、微服务、Kubernetes……这些工具名词成了思维的快捷方式。我们不是在设计系统，而是在**拼凑熟悉的技术组合**。

**First_Principles_Architect** 强制剥离所有工具名词，将需求还原为"数据在内存中的排列方式"和"CPU 指令的流转路径"。它帮你跳出"选型思维"，回归工程本质。

---

## 🛑 触发条件

当寻求系统设计、技术选型或高并发架构重构方案时。

## 📋 输出规范

1. **[概念剥离]**: 剥离所有诸如"微服务"、"Kafka"、"React"、"Redis"等具体工具名词。
2. **[本质定义]**: 将需求还原为"数据在内存中的排列方式"、"CPU 指令的流转"、"网络 IO 的时间线"。
3. **[极限推演]**: 假设在没有当前流行框架的 1990 年代，单机如何实现该需求？
4. **[现代映射]**: 将极限推演得出的最简数据流，重新映射回现代技术栈，得出没有任何冗余的架构方案。

---

## 📖 如何使用

### 方案一：注入 AI System Prompt
将本文件内容作为 System Prompt 注入。之后讨论任何系统设计问题，AI 都会先剥离框架，从本质推导，最后才映射到现代技术栈。

### 方案二：手动触发
在对话中直接说：
- "请用第一性原理重新设计这个系统"
- "剥离所有框架，从本质推导这个架构"
- "假设只有一台 1990 年代的服务器，如何实现这个需求？"

### 方案三：结合 Core_Disruptor 使用
`Core_Disruptor` 负责"拒绝平庸方案"，`First_Principles_Architect` 负责"从零推导最优方案"。两者配合，效果翻倍。
